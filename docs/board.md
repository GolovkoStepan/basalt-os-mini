# M5Stack Cardputer (K132 / ADV)

Карманный компьютер на **ESP32-S3** с 56-клавишной клавиатурой, экраном
240×135, динамиком, микрофоном, ИК-передатчиком, microSD и батареей.
Форм-фактор — «карточка» 84 × 54 × 19.7 мм.

| | |
|---|---|
| **Модели** | **K132** — оригинал; **Cardputer ADV** — ревизия (другая клавиатура, аудиокодек, IMU) |
| **Модуль** | M5StampS3 (оригинал) / M5StampS3A (ADV) |
| **Статус** | проверен на железе 20–21.10.2026: ревизия, flash, память, дисплей, консоль, процесс прошивки (раздел 12) |
| **Документ создан** | 20.10.2026 |

> **Степень доверия.** «документация» — `docs.m5stack.com/en/core/Cardputer`.
> «код M5Cardputer» — прочитано в исходниках библиотеки (`IOMatrix.cpp`,
> `Keyboard_def.h`), это то, что реально исполняется на плате.
> «предположительно» — требует проверки.

## 1. Как опознать ревизию

Ревизии различаются **не корпусом**, а клавиатурой и аудиотрактом:

| | K132 (оригинал) | Cardputer ADV |
|---|---|---|
| Клавиатура | матрица 8×7 через **74HC138**, опрос по GPIO | **TCA8418** по I2C (0x34) |
| Звук | **NS4168** (I2S-усилитель) | **ES8311** кодек (0x18) + NS4150B |
| Микрофон | **SPM1423** (PDM) | аналоговый MEMS через ES8311 |
| IMU | нет | **BMI270** (0x68) |
| Внутренняя I2C | нет | G8/G9 |
| Микрофон и динамик одновременно | **нельзя** (общий G43) | можно (full duplex) |

**Определение в коде:** попробовать I2C на G8/G9 и адрес `0x34` — если отвечает,
это ADV; если нет — оригинал, и G8/G9 остаются линиями матрицы. Так делает espp.

M5GFX (код проверен 20.10.2026 по `M5GFX.cpp`, и именно он исполнялся на плате)
делает иначе — **читает уровни**, не адреса: переводит G8/G9 в `INPUT_PULLDOWN`,
и если оба прочитались в 1, значит на них висят подтяжки I2C — это ADV. Плюс
проверка VAMeter: G5/G6 и адреса `0x40`/`0x41`.

**Проверено на этом экземпляре:** в логе загрузки заводской прошивки
`W (994) M5GFX: [Autodetect] board_M5Cardputer` — значит **оригинал K132**, не
ADV и не VAMeter.

> На оригинале G8/G9/G11 — **адресные линии** клавиатуры. Если случайно
> запустить I2C на G8/G9, клавиатура будет опрашиваться мусором.

## 2. Характеристики

| Параметр | Значение |
|---|---|
| SoC | **ESP32-S3FN8**, Xtensa LX7, 2 ядра, 240 МГц |
| Архитектура | **xtensa** — совпадает с нашей `espressif32@8.0.0`, второй платформы не нужно |
| Flash | **8 МБ** в корпусе модуля (GD, GigaDevice), quad, QIO, 3.3 В |
| PSRAM | **нет, ни в одной ревизии** (часть `FN8` = flash 8 МБ без PSRAM). Официально: «Cardputer does not have a PSRAM» |
| SRAM | 512 КБ |
| Экран | **ST7789V2**, 1.14″, **240×135**, IPS, SPI |
| Клавиатура | **56 клавиш**, матрица 4×14 логически / 8×7 при опросе |
| Звук | 1 Вт @ 8 Ом, I2S |
| Микрофон | MEMS |
| USB | USB OTG (native) + **USB Serial/JTAG**, VID:PID `303A:1001`. Моста UART→USB (CH340/CH9102) **нет**: `/dev/cu.usbmodem*`, не `usbserial*` |
| Wi-Fi | 2.4 ГГц |
| microSD | SPI |
| ИК | TX, до 410 см под 0° |
| Батарея | 120 мА·ч + 1400 мА·ч в основании (всего ~1520 мА·ч) |
| Ток в работе | ~166 мА (клавиатура), ~256 мА (ИК) |
| Ток сна | 0.26 мкА |
| Размер / вес | 84 × 54 × 19.7 мм, 92.3 г |

**Ключевое следствие для ОС:** PSRAM нет, но она и не нужна —
240×135×2 = **64.8 КБ** на полный кадр, это помещается во внутреннюю SRAM
целиком, с запасом на второй буфер. Полностью противоположная ситуация CYD
(там 150 КБ на кадр против 110 КБ крупнейшего блока) и Tab5 (там 1.8 МБ).

## 3. Распиновка

### Экран ST7789V2 (SPI)

| Сигнал | GPIO |
|---|---|
| BL (подсветка, PWM) | **G38** |
| RST | **G33** |
| DC / RS | **G34** |
| MOSI (DAT) | **G35** |
| SCK | **G36** |
| CS | **G37** |

### Клавиатура (оригинал K132) — 74HC138

| Что | GPIO |
|---|---|
| Адрес A0 / A1 / A2 (выходы на 74HC138) | **G8 / G9 / G11** |
| Входы строк Y0…Y6 | **G13, G15, G3, G4, G5, G6, G7** |
| Логика | выходы задают номер строки (0…7), входы читаются с `INPUT_PULLUP`, **нажатие = LOW** |

Порядок пинов подтверждён кодом (код M5Cardputer):

```cpp
const std::vector<int> output_list = {8, 9, 11};
const std::vector<int> input_list  = {13, 15, 3, 4, 5, 6, 7};
```

То есть 8 проходов по строкам, на каждой читается 7 бит → 56 клавиш.
Никакого I2C, никаких прерываний — чистый GPIO. Идеальный первый драйвер.

### Клавиатура (ADV) — TCA8418

| Что | Значение |
|---|---|
| I2C | **G8 (SDA) / G9 (SCL)** |
| Адрес | **0x34** |
| Прерывание | отдельная линия (см. `TCA8418.cpp`) |

### microSD (SPI)

| Сигнал | GPIO |
|---|---|
| CS | **G12** |
| MOSI | **G14** |
| CLK | **G40** |
| MISO | **G39** |

Детекта карты нет — наличие определяется по ответу на инициализацию.

### Звук и микрофон (оригинал)

| Сигнал | GPIO |
|---|---|
| NS4168 BCLK | **G41** |
| NS4168 SDATA | **G42** |
| NS4168 LRCLK | **G43** |
| SPM1423 DAT (PDM) | **G46** |
| SPM1423 CLK (PDM) | **G43** ← **тот же пин!** |

**G43 делится между LRCLK динамика и PDM-клоком микрофона.** Поэтому на
оригинале динамик и микрофон **одновременно работать не могут** — это не
ограничение софта, а физика. На ADV оба идут через ES8311 и работают вместе.

### Прочее

| Что | GPIO |
|---|---|
| ИК-передатчик TX | **G44** |
| Батарея (ADC, делитель 2:1) | **G10** |
| WS2812 RGB LED (на StampS3, питание от линии подсветки) | **G21** |
| Кнопка G0 (BOOT / пользовательская) | **G0** |
| Grove / HY2.0-4P (`PORT.CUSTOM`) | жёлтый **G2**, белый **G1** |

### WS2812 RGB LED

Пин **G21**, светодиод стоит на самом модуле StampS3. Подтверждено дважды:
своей прошивкой на плате и заводской таблицей пинов M5Unified
(`_pin_table_other0`, `board_M5Cardputer → GPIO_NUM_21`). Встречающаяся в
интернете схема «R/G/B на G25/G26/G27» — от другой платы, здесь её нет.

| Параметр | Значение |
|---|---|
| Питание | от линии подсветки **G38**: пока она не поднята, светодиод не горит независимо от данных |
| Защёлкивание цвета | держит последний принятый цвет, пока есть питание; после снятия питания стартует погасшим |
| Порядок байт | **GRB** (не RGB) |
| Кадр | 24 бита, старшим битом вперёд |
| Пауза между кадрами | не меньше 50 мкс по даташиту, **280 мкс** у WS2812B-V5; заводская библиотека M5 использует **300 мкс** |

**Чем гнать биты: RMT, не «дёргать пин в цикле».** Бит кодируется длительностью
импульса с допуском ±150 нс, и любой обработчик прерывания в цикле на C сдвигает
фронт. RMT выщёлкивает уровни из своей памяти независимо от загрузки процессора.

Тайминги, принятые заводской библиотекой M5Unified и проверенные на этой плате:

| Параметр | нс | тиков при 10 МГц |
|---|---|---|
| T0H | 300 | 3 |
| T0L | 900 | 9 |
| T1H | 900 | 9 |
| T1L | 300 | 3 |

**Грабли (каждая даёт полное молчание светодиода, без единой ошибки в логе):**

1. **Память канала вместо FIFO.** `RMT_SYS_CONF_REG.APB_FIFO_MASK` (бит 0) =
   «обращаться к памяти напрямую». Без него записи по адресу памяти уходят в
   FIFO, передатчик читает пустую память и выдаёт нули.
2. **Два делителя частоты.** У RMT есть общий делитель группы
   (`SCLK_DIV_NUM`) и отдельный на канал (`DIV_CNT_CH0`). На этой плате
   **работает только сочетание «общий 1, канальный 8»** (80 МГц / 8 = 10 МГц) —
   то же, что ставит IDF. При обратном сочетании (общий 8, канальный 1) кадры
   не принимались; предположительно частота бита берётся от канального
   делителя, и вместо 10 МГц получалось 80 МГц.
3. **Нулевое слово — конец кадра.** Передатчик останавливается на слове, где
   обе длительности нулевые. Значит хвост блока памяти обязателен нулевым,
   иначе после цвета в линию уйдёт мусор из незаписанных слов.

**Как проверить, не глядя на светодиод:** измерить длительность кадра по
регистру статуса (адрес чтения дошёл до терминатора). 24 бита по 1.2 мкс =
**28.8 мкс**; замерено **29 мкс**. Заметно меньше — частота неверна.

## 4. Экран

ST7789V2, SPI, 240×135, **портретная панель 135×240 с окном 240×135** — при
инициализации нужен `MADCTL` под landscape и правильные `x/y`-offset'ы
(типовая ошибка: картинка «съезжает» на 52/53 пикселя).

Что важно для собственного драйвера:

- Инициализация — десяток команд, всё по даташиту: `SLPOUT`, `COLMOD` (16 бит),
  `MADCTL`, `PORCTRL`, `GCTRL`, `VCOMS`, `LCMCTRL`, `VDVVRHEN`, `VRHS`, `VDVS`,
  `PWCTRL1`, `PVGAMCTRL`, `NVGAMCTRL`, `INVON` (у этой панели цвета
  инвертированы), `NORON`, `DISPON`.
- **Полный кадр — 64.8 КБ.** Это одно окно `COLMOD`-записи, кадр уходит по DMA
  одним куском. При 40 МГц: 64 800 Б × 8 / 40 МГц ≈ **13 мс на кадр** (~77 fps
  теоретический потолок); при 80 МГц — вдвое быстрее.
- Подсветка — PWM на G38. Тот же пин питает WS2812.
- В отличие от Tab5 (MIPI-DSI + TDDI + сброс через I2C-экспандер), здесь
  **драйвер пишется с нуля за один вечер**. Это главная причина, почему
  Cardputer — хороший первый полигон.

**Проверено по исполнявшемуся коду M5GFX** (`M5GFX.cpp`, ветка
`board_M5Cardputer`), а не по даташиту:

| Параметр | Значение |
|---|---|
| Панель | `Panel_ST7789`, `readable = true`, `invert = true` |
| Геометрия панели | **135×240** (портрет), `offset_x = 52`, `offset_y = 40`, `offset_rotation = 0` |
| Поворот | `setRotation(1)` → рабочие 240×135 |
| SPI-хост | `SPI3_HOST`, `spi_mode = 0`, **`spi_3wire = true`** (MISO не используется) |
| Частота записи | **40 МГц** |
| Частота чтения | **16 МГц** |
| Подсветка | `_set_pwm_backlight(G38, ch 7, 256 Гц, invert=false, offset=16)` |

При `setRotation(1)` (рабочий landscape) M5GFX пересчитывает смещения и
`MADCTL`; это же пересчитано и проверено своей прошивкой (21.10.2026):

| Параметр | Значение |
|---|---|
| `MADCTL` (rotation 1) | **0x6C** = `MV | MX | MH | BGR` |
| Смещение по x (прибавляется к `CASET`) | **40** |
| Смещение по y (прибавляется к `RASET`) | **53** |

`rowstart = 53`, а не 52: при `MX` адресация строк идёт с другого конца памяти
(240 − (135 + 52) = 53). Портретные `offset_x = 52`, `offset_y = 40` из
таблицы выше при повороте меняются местами и пересчитываются — брать их для
landscape напрямую нельзя.

Отсюда практические следствия:

- **40 МГц уже проверены вендором на этой панели** — можно начинать с них, а не
  с осторожных 10–20 МГц. 60 и 80 МГц — вопрос эксперимента (см. раздел 11).
- `offset_x = 52` — это и есть та «съезжающая картинка», о которой выше.
- `spi_3wire` + `pin_miso = NC`: отдельного провода `MISO` нет. Панель при этом
  читаема — M5GFX определяет её командой `RDDID` по той же линии в
  трёхпроводном режиме. Для драйвера это значит: писать можно сразу, а чтение —
  только если действительно понадобится.
- `invert = true` — цвета инвертированы на уровне панели (`INVON`).
- Формула 13 мс на кадр при 40 МГц из списка выше — расчёт, а не измерение.

## 5. Клавиатура

- 56 клавиш: 4 ряда × 14 колонок в раскладке, но электрически — 8 строк × 7
  столбцов через демультиплексор 74HC138.
- Опрос: выставить 3 бита адреса → прочитать 7 входов. 8 итераций.
- Антидребезг и автоповтор — софтом.
- `Fn` даёт слой спецклавиш: `Esc`, `F1…F12`, стрелки, `Delete`, `Tab`
  (см. таблицу в документации espp — она же удобный чеклист для своего драйвера).
- Нажатие фиксируется как смена состояния: сканировать надо чаще, чем человек
  отпускает клавишу — 10 мс достаточно.

---

### Текстовый режим — почему 40×15

Аппаратные числа, которые определяют пригодность платы для терминала:

| Параметр | Значение |
|---|---|
| Ячейка символа 6×9 (глиф 5×7 + зазор) | **40 колонок × 15 строк** (240/6 и 135/9 — ровно) |
| Символов на экране | 600 |
| Текстовая матрица (символ + атрибут) | 1.2 КБ |
| Полоса рендера одной строки | 240 × 9 × 2 Б = 4.3 КБ, **0.87 мс** при 40 МГц SPI |
| Полный кадр | 64.8 КБ, **~13 мс** при 40 МГц (~77 fps потолок) |

Следствие: кадровый буфер **не нужен** — достаточно полосы в одну строку и
перерисовки по изменённым строкам. Это освобождает ~60 КБ SRAM, что на плате
без PSRAM принципиально.

Разрешение 40×15 ставит плату в исторический класс карманных машин
(TRS-80 Model 100 — 40×8, HP 200LX — 40×16).

## 6. Питание и USB

- Два аккумулятора: 120 мА·ч в корпусе + 1400 мА·ч в основании, с зарядом,
  boost и buck на борту.
- **Зарядка только при переключателе в положении ON** — иначе не заряжается.
- Кнопка G0 — одновременно BOOT и пользовательская.
- **Режим загрузки:** переключатель питания в **OFF**, зажать **G0**, подать
  питание, отпустить G0.
- USB: native OTG + USB Serial/JTAG. Для консоли без IDF —
  **USB Serial/JTAG на 115200** (это не UART0, а отдельный периферийный блок;
  он же даёт отладку и `printf` без внешнего переходника).

## 7. Память и разделы

| Что | Значение |
|---|---|
| Flash | 8 МБ |
| SRAM | 512 КБ |
| PSRAM | нет |
| Кадр 240×135 RGB565 | 64.8 КБ |
| Два буфера | 129.6 КБ |
| Разделы | стандартные `default.csv` — **переопределить** под свой загрузчик/ФС, снять `pio run -t partitiontable` после первой сборки |

**Измерено на этом экземпляре** (лог `heap_init` заводской прошивки):

| Область | Адрес | Размер |
|---|---|---|
| D/IRAM | `0x3FCA79A8` | **263 КБ** |
| STACK/DIRAM | `0x3FCE9710` | 21 КБ |
| DRAM | `0x3FCF0000` | 32 КБ |
| RTCRAM | `0x600FE000` | 8 КБ |

Строк про PSRAM в логе **нет** — независимое подтверждение, что её нет.
Сумма ~324 КБ, а не 512: остальное занято ROM и служебными областями.

Заводская разметка (из снятого дампа, `0x8000`):

| Метка | Тип | Offset | Размер |
|---|---|---|---|
| `nvs` | data/nvs | `0x009000` | 20 КБ |
| `phy_init` | data/phy | `0x00F000` | 4 КБ |
| `factory` | app | `0x010000` | **4 МБ** |
| `storage` | data/fat | `0x410000` | 1 МБ |

Разметка **4-мегабайтная**, хотя флешка на 8: всё выше `0x510000` —
сплошные `0xFF`, вторая половина чипа не использовалась никогда. Нам это на
руку: под свою ОС места с запасом, `huge_app.csv` не понадобится.

Бюджет для собственной ОС (ориентир, при отказе от IDF-рантайма):

| Потребитель | Оценка |
|---|---|
| Ядро + драйверы | ~40 КБ |
| Кадровый буфер | 65 КБ |
| Кэш ФС (16 блоков по 512 Б) | 8 КБ |
| Шелл + буферы | ~10 КБ |
| mruby (урезанная сборка) | 80–120 КБ |
| **Итого** | **~210–250 КБ** из ~400 доступных |

То есть **mruby помещается**, но с настройкой конфигурации (`MRB_USE_FLOAT32`,
урезанные gem'ы). PSRAM нет — это главный аргумент урезать mruby, а не тащить
полный.

## 8. Готовая база `platformio.ini`

Платформа та же, что у `pulsar` — **вторая платформа не нужна**, `.clangd`
работает без правок. Это существенное преимущество перед Tab5.

```ini
[env:cardputer]
platform = espressif32@8.0.0
board = esp32-s3-devkitc-1
framework = arduino
board_build.flash_size = 8MB
board_upload.flash_size = 8MB
upload_speed = 1500000
monitor_speed = 115200
build_flags =
    -DCORE_DEBUG_LEVEL=3
    -DARDUINO_USB_CDC_ON_BOOT=1
    -DARDUINO_USB_MODE=1
lib_deps =
    https://github.com/m5stack/M5Cardputer
```

**Не добавлять** `-DBOARD_HAS_PSRAM` — PSRAM физически нет, с этим флагом
прошивка упадёт при инициализации.

Документация M5Stack предлагает `platform = espressif32@6.7.0`; у нас
зафиксирована 8.0.0 — проверить на плате, при проблемах с USB-CDC откатиться
локально для этого проекта.

## 9. Грабли

| Симптом | Причина | Решение |
|---|---|---|
| Не прошивается | переключатель не в OFF / не зажат G0 | OFF → зажать G0 → подать питание → отпустить |
| Не заряжается | переключатель в OFF | включить |
| Мусор в клавиатуре | I2C на G8/G9 у оригинала (это линии матрицы) | сначала определить ревизию |
| Клавиши «залипают» | нет антидребезга | опрос каждые 10 мс + фильтр |
| Картинка смещена | неверные offset'ы 240×135 / неверный `MADCTL` | подобрать по даташиту панели |
| Цвета инвертированы | у панели нужен `INVON` | добавить `INVON` в init |
| Динамик молчит | конфликт с микрофоном на G43 (оригинал) | не включать микрофон одновременно |
| Прошивка падает при старте | `-DBOARD_HAS_PSRAM` | убрать флаг |
| `pio device monitor` не видит порт | это USB Serial/JTAG | `-DARDUINO_USB_CDC_ON_BOOT=1`, порт `/dev/cu.usbmodem*` |

## 12. Процесс прошивки и чтения лога

Разобрано 21.10.2026 на извлечённом модуле M5StampS3 (тот же SoC, что в
Cardputer) и проверено end-to-end. Вывод «плата сломалась / нет питания»
**опровергнут**: чип исправен, все заливки проходили с проверкой хеша.

### Штатная заливка — без кнопок

```bash
pio run -e <env> -t upload
```

Работает **без единого нажатия**. Проверено на трёх прошивках (`bringup`,
`console`, `hello`): `esptool` сам переводит чип в download через DTR/RTS.
Удерживать G0 для каждой прошивки **не нужно**.

### Главная грабля: чтение лога выключало прошивку

Полдня ушло на это. Симптом: прошивка залита (`Hash of data verified`),
LED мигает и подсветка горит, а в логе **ни байта**, и `esptool` не
подключается. Выглядит как мёртвая плата.

Причина: скрипт чтения при открытии порта делал `DTR=0, RTS=1`. На USB
Serial/JTAG (любой S3 без моста UART) это **не сброс, а команда «войти в режим
загрузчика»**. Чип послушно уходил в download mode и оставался там: порт есть,
`esptool` отвечает, а прошивка не исполняется — отсюда пустой лог. И это же
объясняет, почему потом не работал автоподключ при заливке: чип уже сидел в
загрузчике, но не в том состоянии, которого ждал `esptool`.

Проверка, что чип в загрузчике, а не в прошивке:

```bash
esptool --chip esp32s3 -p <порт> --before no-reset --after no-reset chip-id
# «Staying in bootloader» = прошивка не исполняется
```

Правильный сброс для S3 — через `esptool`, он умеет это по USB:

```bash
esptool --chip esp32s3 -p <порт> --before no-reset --after hard-reset read-mac
# после этого порт пересоздаётся, читать с паузой ~1 с
```

`tools/serial-read.py` исправлен: DTR/RTS не трогает, только слушает.

### Кнопки: когда действительно нужны

| Сценарий | Кнопки |
|---|---|
| Штатная заливка | **не нужны** |
| Чип в загрузчике, надо просто запустить прошивку | **RST** (коротко, без G0) |
| `esptool` не подключается вообще | **G0 + RST**: зажать G0 → нажать-отпустить RST → отпустить G0 |

На извлечённом модуле кнопки открыты: **RST** и **G0** — рядом. На Cardputer
G0 выведена на боковину, RST доступна только со снятой задней крышкой.

### Что чем проверяется

| Симптом | Что это значит |
|---|---|
| Порт есть, лог идёт | всё работает |
| Порт есть, лога нет, `chip-id` говорит `Staying in bootloader` | чип в загрузчике → сброс через `esptool` |
| Порт есть, лога нет, LED/подсветка живут | прошивка работает, молчит только вывод → искать в коде |
| Порта нет совсем | питание или кабель; проверить `ioreg -p IOUSB` |

Отсутствие лога **не означает**, что прошивка не залилась. Поэтому в `hello`
есть три независимых канала: лог, LED и echo.

### Порт пересоздаётся и переименовывается

Наблюдались `usbmodem101` и `usbmodem1101` на одном физическом порту мака
(`LOCATION=1-1`). После каждого сброса узел `/dev/cu.usbmodem*` исчезает и
появляется заново — открывать порт сразу после сброса нельзя, нужно
дождаться. Скрипты определяют порт по VID `0x303A`, а не по имени.

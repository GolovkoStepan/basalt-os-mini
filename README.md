# BASALT-OS-MINI

[![сборка и тесты](https://github.com/GolovkoStepan/basalt-os-mini/actions/workflows/build.yml/badge.svg?branch=master)](https://github.com/GolovkoStepan/basalt-os-mini/actions/workflows/build.yml)

Терминальная операционная система на **ESP32-S3**, которую мы пишем сами:
своя точка входа, своя таблица векторов, своя карта памяти, свой тик, свой
tty, свой шелл. Без Arduino и без FreeRTOS.

Название «mini» — не про игрушку, а про **эталонную реализацию**: отсюда
потом форкается `basalt-os` для M5Stack Tab5. Всё, что не зависит от
архитектуры (tty, ANSI, VFS, шелл, утилиты), пишется здесь один раз и
переносится, а не пишется заново.

| | |
|---|---|
| **Плата** | **LilyGO T-Display-S3** — [`docs/board.md`](docs/board.md) |
| **SoC** | ESP32-S3R8, 2× Xtensa LX7 240 МГц, 512 КБ SRAM, **8 МБ PSRAM**, 16 МБ flash |
| **Экран** | ST7789 1.9″, **320×170**, 8-битная параллельная шина (i80) |
| **Что умеет** | [`docs/FUNCTIONALITY.md`](docs/FUNCTIONALITY.md) |
| **Порядок работ** | [`docs/ROADMAP.md`](docs/ROADMAP.md) |
| **Что сделано и почему** | [`docs/JOURNAL.md`](docs/JOURNAL.md) |
| **Состояние** | A0–A3, A7 и A9 закрыты (06–07.11.2026): своя точка входа, консоль, паника, таблица векторов и карта памяти; текст 53×17 с кириллицей и прокруткой; ввод с мака через `tty` (канон и raw, `Backspace` по UTF-8, зеркало в USB, G0 как `Ctrl-C`); шелл с редактированием строки, историей, разбором с кавычками, командами `help`/`top`/`free` и полноэкранным `edit` (проверен на плате 07.11.2026). Хранилище — **встроенный flash 16 МБ** (SD-карты в проекте нет и не будет, решение 06.11.2026): свой драйвер flash, своя таблица разделов и **своя ФС `BFS`** с копированием при записи (COW), проверенная на живой плате (`make fs`), VFS, команды `ls`/`cat`/`cd`/`pwd`/`stat`/`mkdir`/`rm`/`rmdir`/`cp`/`mv`/`df` и перенаправления `>`/`>>`/`<`/`|`. **A8, время** — сделано и проверено на плате 07.11.2026: свой календарь и часы без RTC (`time/`), `/etc/clock`, метки файлов, `ls -l`, `date set`, `sleep`, `alarm` |

## Плата, на которую проект переехал

До 05.11.2026 проект жил на M5Stack Cardputer. Переезд сделан по одной
причине: **у Cardputer нет PSRAM**, и весь проект был построен вокруг этого
ограничения — вместо кадрового буфера полоса в одну строку, вместо
файловой системы в flash — ничего, вместо mruby — mruby/c.

На T-Display-S3 тот же чип (значит, весь оплаченный `arch/xtensa` переехал
без правок), но есть 8 МБ PSRAM и 16 МБ flash. Кадровый буфер 320×170×2 =
108 КБ теперь помещается целиком.

Cardputer не выброшен, но и не живёт здесь: его терминал переехал в отдельный
проект [`capsh`](../capsh) — «прошивка с периферией, но без своего ядра»,
на Arduino core. Документ платы уехал туда же, в `capsh/docs/board.md`, и
второй копии нет. В этом репозитории остались `env:bare` / `env:console` /
`env:bringup` как запасной путь: они собираются и работают, пока `capsh` не
проверен на живой плате, и удаляются после этого.

## Документы

```
docs/
├── board.md            железо T-Display-S3: пины, i80, память, грабли, замеры
├── FUNCTIONALITY.md    что система умеет (источник истины по терминалу)
├── ROADMAP.md          вехи A0–A12
└── JOURNAL.md          журнал: что сделано, зачем и как проверить
```

`docs/board.md` — единственный документ платы, копии нет. Измеренные данные
(скорость шины, свободный heap, режим PSRAM) пишутся сюда, а не в переписку.

`docs/JOURNAL.md` — объяснение шагов бытовым языком, для того, кто читает код
и не является экспертом в ОС. Запись добавляется только после проверки на
плате.

## Проверки

| Что | Чем | Плата нужна |
|---|---|---|
| логика на маке | `pio test -e native` | нет |
| собранный образ по символам | `./tools/check-image.sh tdisplay` | нет |
| лог живой прошивки | `./tools/smoke.sh tdisplay` | да |

Первые две идут в CI на каждый push (`.github/workflows/build.yml`), плюс
сборка всех env. Третья — вручную: тики и паника видны только в логе с платы,
а раннера с T-Display-S3 нет.

## Команды

`make` — короткие имена для того, что иначе надо помнить: у половины команд
есть env, половина живёт в `tools/` своими скриптами. Логики в `Makefile` нет,
он только называет команды, поэтому `pio` остаётся доступен напрямую.

```bash
make                 # собрать env:tdisplay
make help            # список целей
make verify          # то же, что CI: тесты, все env, проверка образов
```

| Команда | Что делает | Плата |
|---|---|---|
| `make build [ENV=…]` | собрать env, по умолчанию `tdisplay` | нет |
| `make flash [ENV=…] [PORT=…]` | собрать и залить | да |
| `make log [SECONDS=…]` | читать лог платы, по умолчанию 15 с | да |
| `make monitor` | интерактивный монитор, только живой терминал | да |
| `make smoke [ENV=…]` | залить и сверить лог с «признаком успеха» | да |
| `make probe` | залить щуп и прочитать замеры PSRAM и heap | да |
| `make fs` | залить щуп файловой системы BFS | да |
| `make test` | тесты на маке (Unity) | нет |
| `make check [ENV=…]` | проверить образ по символам | нет |
| `make verify` | тесты, сборка всех env, проверка образов | нет |
| `make compiledb [ENV=…]` | база для clangd | нет |
| `make reset` | вывести плату из загрузчика сбросом | да |
| `make id`, `make backup` | чип, flash, MAC; бэкап оригинальной прошивки | да |
| `make clean`, `make erase` | снести сборку; стереть flash | нет / да |
| `make devices` | список последовательных портов | нет |

`ENV` по умолчанию `tdisplay` — это основная плата. `ENV=bare` — Cardputer.

Заливка файла в ФС платы — не через `make`, а скриптом по той же консоли:

```bash
./tools/xsend.sh notes.txt /etc/notes.txt   # XMODEM, ~21 КБ/с
```

Посмотреть, что лежит в ФС, можно и без работающей прошивки — скрипт читает
раздел через загрузчик и разбирает BFS на маке:

```bash
./tools/fsdump.py                # дерево ФС
./tools/fsdump.py --save fs.bin  # дамп остаётся, дальше --read fs.bin
```

`make compiledb` собирает базу под **один** env: файл
`compile_commands.json` один, базы разных env перезаписывают друг друга.
Для работы с `arch/xtensa` нужна база от `tdisplay` — она и делается по
умолчанию.

## Почему терминал, а не окна

- **53×17 при ячейке 6×9.** Печатать на маке по USB, смотреть на устройстве.
  Позже то же самое по Wi-Fi через `telnet` — и тогда размер экрана перестаёт
  быть ограничением вообще.
- **Кадровый буфер 108 КБ живёт в PSRAM**, в SRAM остаются ядро и драйверы.
  Это ровно та дисциплина, которая понадобится на P4: там PSRAM 32 МБ, и
  соблазн «всё в PSRAM» так же вреден, как её отсутствие.
- **ANSI-подмножество**: tty ведёт себя как настоящий, поэтому возможны
  чужие терминальные программы, постраничный просмотр и удалённые машины.
- **Клавиатуры на плате нет** — и это сознательно: ввод через терминал мака
  дешевле любой матрицы, а две кнопки закрывают `Ctrl-C` и `Esc`.

## Что здесь делается с нуля

Всё, что относится к системе, — включая то, что обычно берут из SDK:

- точка входа и линкер-скрипт, таблица векторов, `arch/xtensa`;
- консоль USB Serial/JTAG по регистрам, тик на SYSTIMER, своя паника;
- tty с ANSI, шелл, редактирование строки и полноэкранный редактор `edit`;
- файловая система во flash (A9): драйвер flash, таблица разделов, ФС `BFS`
  с копированием при записи, VFS и команды над файлами;
- планировщик и переключение контекста на Xtensa.

**Что берём готовым и почему:** драйвер экрана — через `esp_lcd`, потому что
i80 в ESP32-S3 (`LCD_CAM`) занимает больше кода, чем весь остальной `arch/`,
а учит меньше. Интерфейс при этом свой (`drivers/lcd.h`), реализация под ним
заменяема. Wi-Fi и lwIP — блоб и стек, их физически нельзя написать самому;
это отдельная веха с возможным откатом.

## Принципы

1. **Граница syscall — даже когда железо её не проверяет.** На S3 нет user
   mode: «системный вызов» — обычный вызов функции. Но интерфейс всё равно
   оформляется таблицей вызовов, чтобы при форке на P4 включить изоляцию
   без переписывания логики.
2. **`arch/` с первого дня.** Переключение контекста, trap, старт — за
   интерфейсом, без `#ifdef` по всему ядру. Переезд с Cardputer на
   T-Display-S3 это уже подтвердил: `arch/xtensa` и `ld/memory.ld` переехали
   без единой правки, поменялся только драйвер индикатора.
3. **ANSI-подмножество, а не свой API.** Терминал должен вести себя как
   терминал — это критерий качества.
4. **Хост для отладки, плата для проверки.** Логика tty, FAT32 и шелла
   отлаживается на маке; заливка — проверка, а не способ отладки.
5. **Каждая веха заканчивается тем, что можно нажать.**

## Структура

```
basalt-os-mini/
├── README.md
├── AGENTS.md                правила этого репозитория
├── Makefile                 короткие имена команд: make help
├── .clangd                  пути xtensa-тулчейна
├── platformio.ini           [base] + env: tdisplay, tdisplay-panic, probe, lcd, text, tty, shell, flash, fs, bare, bare-panic, console, hello, bringup, native
├── partitions.csv           своя таблица разделов: 2 МБ приложению, 14 МБ данным
├── ld/memory.ld             карта памяти приложения (своя, не из IDF)
├── boards/tdisplay_s3/      board_pins.h основной платы
├── boards/cardputer/        board_pins.h Cardputer (уезжает в capsh)
├── docs/
├── tty/                     line discipline: канон и raw, эхо, Backspace, Ctrl-C/D
├── shell/                   шелл: редактор строки, история, разбор, план, XMODEM, less, edit
├── storage/                 хранилище: таблица разделов, своя ФС BFS, VFS
├── tools/                   serial-read, xsend, fsdump, flash-backup, check-image, smoke, reset
├── test/                    хостовые тесты (Unity)
├── src/                     точки входа env'ов + CMakeLists с выбором платы
├── arch/xtensa/             старт, векторы, паника, консоль, тик, индикатор, куча, flash
└── .github/workflows/       CI: сборка всех env и тесты
```

**Пины платы — в `boards/<плата>/board_pins.h`**, путь подставляется сборкой.
Магических чисел GPIO в логике нет. Различие между платами решается в
`src/CMakeLists.txt` (какой файл индикатора собрать), а не `#ifdef` в коде:
`arch/` не должен знать, на какой плате он запущен.

## Отношения с другими репозиториями

- **`basalt-os`** (Tab5, ESP32-P4) — отдельный репозиторий, форкается отсюда
  в точке MVP (после A7). **На паузе** с 05.11.2026: плата заказана, но
  решение о своём ядре против готового не принято.
- **`capsh`** (Cardputer) — будущий отдельный проект: «прошивка с
  периферией, linux-like, без своего ядра». Появится, когда закончится
  переезд; документ платы уже готов и уедет туда.

Общих исходников между репозиториями нет. Форк означает копию, а не
submodule.

## Правила репозитория

Свои — в [`AGENTS.md`](AGENTS.md). Коротко: идентификаторы английские,
комментарии и документы русские, коммиты делает только автор, `.pio/`,
`compile_commands.json`, `backup/` в git не попадают.

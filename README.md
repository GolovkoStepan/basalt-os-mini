# BASALT-OS-MINI

Терминальная операционная система для **M5Stack Cardputer** (ESP32-S3).
Без графического интерфейса: экран — текстовый терминал 40×15, ввод —
физическая клавиатура.

Название — «mini» не потому, что игрушка, а потому, что это **эталонная
реализация**: отсюда потом форкается `basalt-os` для M5Stack Tab5. Всё, что
не зависит от архитектуры (FAT32, tty, ANSI, шелл, утилиты), пишется здесь
один раз и переносится, а не пишется заново.

| | |
|---|---|
| **Плата** | M5Stack Cardputer, K132 (оригинал) — [`docs/board.md`](docs/board.md) |
| **SoC** | ESP32-S3FN8, 2× Xtensa LX7 240 МГц, 512 КБ SRAM, **без PSRAM** |
| **Что умеет** | [`docs/FUNCTIONALITY.md`](docs/FUNCTIONALITY.md) |
| **Порядок работ** | [`docs/ROADMAP.md`](docs/ROADMAP.md) |
| **Соседний проект** | `basalt-os` — отдельный репозиторий, Tab5, форк после MVP |
| **Состояние** | плата на руках, код не начат |

## Документы

```
docs/
├── board.md           железо Cardputer: пины, драйверы, грабли, замеры
├── FUNCTIONALITY.md   что система умеет (источник истины по терминалу)
└── ROADMAP.md         вехи A0–A12
```

`docs/board.md` — единственный документ платы, копии нет. Измеренные данные
(скорость SPI, карта `Fn`, размер свободного heap) пишутся сюда, а не в
переписку.

## Почему терминал

- **240×135 при ячейке 6×9 — ровно 40×15.** Исторический класс карманных
  машин: TRS-80 Model 100 — 40×8, HP 200LX — 40×16.
- **Кадровый буфер не нужен.** Полоса рендера одной строки — 4.3 КБ,
  перерисовка по изменённым строкам. На плате без PSRAM это освобождает
  ~60 КБ, то есть разницу между «влезает Ruby» и «не влезает».
- **Клавиатура — настоящая**: 56 клавиш плюс слой `Fn` со стрелками, `Esc`,
  `F1…F12`. Для терминала это полный набор ввода.
- **ANSI-подмножество**: tty ведёт себя как настоящий, поэтому возможны
  чужие терминальные программы, постраничный просмотр и удалённые машины.

## Что здесь делается с нуля

Всё, включая то, что обычно берут из SDK:

- точка входа и линкер-скрипт, таблица векторов, `arch/xtensa`;
- драйвер ST7789 (SPI, init по даташиту, DMA);
- драйвер клавиатуры (матрица 8×7 через 74HC138);
- драйвер SD (SPI) и **FAT32** с чтением и записью;
- планировщик, переключение контекста на Xtensa;
- tty с ANSI, шелл, редактор.

Заимствуется только то, что физически невозможно написать самому: бинарный
блоб Wi-Fi и lwIP. Это честно помечено в роадмапе как отдельная веха
с возможным откатом.

## Принципы

1. **Граница syscall — даже когда железо её не проверяет.** На S3 нет user
   mode: «системный вызов» — обычный вызов функции. Но интерфейс всё равно
   оформляется таблицей вызовов, чтобы при форке на P4 включить изоляцию
   без переписывания логики.
2. **`arch/` с первого дня.** Переключение контекста, trap, старт — за
   интерфейсом, без `#ifdef` по всему ядру. От этого зависит, насколько
   дешёвым будет форк.
3. **FAT32 родная ФС.** Карта читается на маке без инструментов, и изучается
   настоящая файловая система, а не игрушечная.
4. **ANSI-подмножество, а не свой API.** Терминал должен вести себя как
   терминал — это критерий качества.
5. **Хост для отладки, плата для проверки.** Логика tty, FAT32 и шелла
   отлаживается на маке; заливка — проверка, а не способ отладки.
6. **Каждая веха заканчивается тем, что можно нажать.**

## Отношения с basalt-os

Это **разные репозитории**, потому что там разная архитектура, разный
тулчейн (Xtensa против riscv32) и, по правилу, нет общих исходников.

- **Источник истины по терминалу — этот проект.** Спецификация tty, FAT32,
  шелла и утилит живёт в `docs/FUNCTIONALITY.md` здесь.
- **`basalt-os` форкается в точке MVP** (после вехи A7), а не пишется
  параллельно. До этого он остаётся документом.
- **Расходятся только `arch/` и модель памяти.** Всё остальное должно
  переноситься копированием каталогов, а не переписыванием.
- **Общих исходников между репозиториями нет.** Форк означает копию, а не
  submodule.

## Правила репозитория

Свои — в [`AGENTS.md`](AGENTS.md). Коротко: идентификаторы английские,
комментарии и документы русские, коммиты делает только автор, `.pio/`,
`compile_commands.json`, `backup/` в git не попадают.
